# M1 Record

> 2026-10-24. Goal (10/25 checkpoint): open `tojime_no_siora/002` in the browser, click Translate, and see a real zh-Hans translation from `deepseek-flash`, each line matching its oracle box on the image.

## How to run

See "Run the app" in the README. The DB is `runs/fukidashi.db` (gitignored); the import script can be re-run without creating duplicate rows.

## Structure

| Part | Location |
|---|---|
| Schema | `backend/fukidashi/schema.sql`: `books`, `pages`, `segments`, `runs`, `translations` |
| Import | `backend/fukidashi/datasets/importer.py` + `scripts/import_openmantra.py` |
| `baseline` | `backend/fukidashi/pipeline/baseline.py`, shared by the API and `scripts/m0_first_call.py`; every call goes through `LLMClient` |
| API | `backend/fukidashi/api/pages.py`: `GET /api/pages`, `GET /api/pages/{book}/{index}`, `…/image`, `POST …/translate` |
| Service / SQL | `backend/fukidashi/runs.py` (translates a page and records a Run), `backend/fukidashi/store.py` (SQL). In M1 this was still inside `api/pages.py`; it was extracted before M2 |
| Frontend | `frontend/`: Vite + React + TypeScript, page list → page view; the dev server proxies `/api` to `:8000` |

## Design decisions

- **Import upserts with `ON CONFLICT DO UPDATE`, not `INSERT OR REPLACE`.** The latter deletes and re-inserts, which changes `segments` ids and leaves `translations` pointing at rows that no longer exist. A test covers this.
- **A Run is written first and updated later.** Translate inserts a row with `status = 'running'` (committed right away, so no write lock is held during the LLM call) and finishes it as `succeeded` or `failed`. A `failed` Run writes no translations but keeps `error` and `attempts_json` (the raw responses and parse errors).
- **A page shows its latest `succeeded` Run.** If a second Translate fails, the page still shows the previous good translation, and the error is shown separately.
- **Usage follows M0's rules:** `runs.input_tokens` / `output_tokens` are sums over calls with known usage, NULL (not 0) when none is known; `unknown_usage_calls` is recorded separately; `cost_usd` is NULL when no prices are configured.
- **The prompt holds only the Japanese text and the boxes, never the reference translations.** A test checks this, because `segments` stores `text_zh_hant` and `text_en` too, and this is where evaluation is most likely to go wrong later.
- **A Segment's id is its position in `annotation.json` (`idx`).** It is at once the region id in the prompt, the number on the box badge and the row number in the list; boxes and translations line up through it.
- **The frontend positions boxes in percent** (`x / naturalWidth`), so resizing the image needs no size listener.

## Verification

| Item | Result |
|---|---|
| Real call | `tojime_no_siora/002`, Translate clicked in the browser: 922 input / 286 output tokens, about 4 s, $0.00062 (peak price). The translation is still there after a reload |
| Box alignment | All 5 boxes sit on their speech bubbles; hovering a row on the right highlights its box |
| Page without segments | `tojime_no_siora/033`: Translate is disabled and the page says "This page has no text regions." |
| Error state | With the backend stopped, Translate shows a red error, keeps the previous translation, and the button recovers |
| M0 script | `--dry-run` and one real call (same page, 922 / 311 tokens) both work |
| Tests | `uv run pytest`: re-running the import, API smoke tests with the LLM mocked (success, retry on empty content, 502 after two parse failures with the previous translation kept, no request for a page without segments, no reference translation in the prompt) |

M1 made 2 real calls (1 from the browser, 1 from the M0 script, both on `tojime_no_siora/002`), about $0.0013; the whole project's ledger in `runs/usage.jsonl` was about $0.004 at that point. Both calls had 768 input tokens served from cache (same prompt prefix as the M0 call), but the ledger still charges full price, so it overstates.

## Not done / not verified

- Only 1 page was translated (`tojime_no_siora/002`). Other books (images 824 / 836 px wide) and pages with many boxes were checked for layout only.
- Provider errors (authentication failure, rate limit) were not tried in the browser. The API maps them (`backend/fukidashi/llm/errors.py`), but only the 502 parse-failure path is tested.
- No concurrency guard: clicking Translate twice on one page creates two Runs (the button is disabled during the request, but the server has no lock).
- `GET /api/pages` returns all 214 pages at once, with no pagination; enough for this dataset.
- No frontend tests.
- A `runs.status = 'running'` row stays `running` if the server is killed mid-request. Reliability work in M2 handles it.
- The zh-Hant reference is shown as is, not converted to Simplified Chinese; OpenCC is left to M2's evaluation.

## An environment issue

The backend / frontend entries in `.claude/launch.json` did not start in the Claude desktop app's preview: the processes ran but never listened on their ports, with both `uv run` and `.venv/bin/python`. Verification used `uv run uvicorn …` and `npm run dev` from a shell instead, and the browser pane opened `http://localhost:5173` fine. The cause is unknown; possibly macOS's permission prompt for `~/Documents`.
