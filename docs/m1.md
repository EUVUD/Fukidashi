## 设计上的几个决定

- **Import 用 `ON CONFLICT DO UPDATE`，不用 `INSERT OR REPLACE`。** 后者会删掉再插入，`segments` 的 id 变了，`translations` 就指向不存在的行。有测试盖住。
- **Run 先写后改。** Translate 开始时插入一行 `status = 'running'`（立刻 commit，LLM 调用期间不占写锁），结束时改成 `succeeded` 或 `failed`。`failed` 的 run 不写 translations，但保留 `error` 和 `attempts_json`（原始响应和 parse error）。
- **页面显示最新一次 `succeeded` 的 run。** 再点一次 Translate 失败，页面上还是上一次的好译文，错误单独显示。
- **Usage 的口径沿用 M0：** `runs.input_tokens` / `output_tokens` 是已知 usage 的调用之和，一个都不知道时是 NULL，不是 0；`unknown_usage_calls` 单独记；价格没配时 `cost_usd` 是 NULL。
- **Prompt 里只有日文和 box，不含参考译文。** 有测试检查这一点，因为 `segments` 表里同时存着 `text_zh_hant` 和 `text_en`，后面做 eval 时这里最容易出事。
- **Segment 的 id 是 `annotation.json` 里的顺序（`idx`）。** 它同时是 prompt 里的 region id、图上 box 角标的数字、右侧列表的序号。box 和译文靠这个对上。
- **Frontend 的 box 用百分比定位**（`x / naturalWidth`），所以图片缩放时不需要监听尺寸变化。

## 验证

| 项目 | 结果 |
|---|---|
| 真实调用 | `tojime_no_siora/002`，浏览器里点 Translate：922 input / 286 output tokens，约 4 s，$0.00062（高峰价）。重新加载页面后译文还在 |
| Box 对齐 | 5 个 box 都落在对应的气泡上，hover 右侧一行会高亮对应的 box |
| 0-segment 页面 | `tojime_no_siora/033`：Translate 禁用，显示 “This page has no text regions.” |
| 错误状态 | 关掉 backend 再点 Translate：显示红色错误，上一次的译文保留，按钮恢复 |
| M0 script | `--dry-run` 和一次真实调用（同一页，922 / 311 tokens）都正常 |
| 测试 | `uv run pytest`：import 重复运行、API smoke（LLM mocked：成功、空 content 重试、两次解析失败返回 502 且保留上一次译文、0-segment 页面不发请求、prompt 不含参考译文） |

M1 的真实调用一共 2 次（浏览器 1 次，M0 script 1 次，都在 `tojime_no_siora/002`），约 $0.0013；`runs/usage.jsonl` 里整个项目至今累计约 $0.004。这两次调用都有 768 个 input tokens 命中缓存（和 M0 那次的 prompt 前缀相同），账本仍按全价计，会高估。

## 没做 / 没验证

- 只跑了 1 页（`tojime_no_siora/002`）。别的作品（图片 824 / 836 宽）和其他 box 密集的页面只看了布局，没有翻译过。
- 没有测过 provider 报错（认证失败、限流）在浏览器里怎么显示；API 层有映射（`backend/fukidashi/llm/errors.py`），只测过 502 的解析失败路径。
- 没有并发保护：同一页连点两次 Translate 会产生两个 run（按钮在请求期间是禁用的，但没有服务端锁）。
- `GET /api/pages` 一次返回 214 页，没有分页，对这个数据量够用。
- 没有前端测试。
- `runs.status = 'running'` 的行，如果服务在请求中途被杀掉，会一直停在 `running`。M2 做 reliability 时再处理。
- 参考译文（zh-Hant）直接显示，没有转简体。OpenCC 留给 M2 的 eval。

## 环境上的一个坑

`.claude/launch.json` 里的 backend / frontend 在 Claude desktop app 的 preview 里没有启动成功：进程在跑，但一直没有监听端口，`uv run` 和直接调 `.venv/bin/python` 都一样。验证时改用 shell 里的 `uv run uvicorn …` 和 `npm run dev` 启动，浏览器 pane 打开 `http://localhost:5173` 没问题。原因没有查清，怀疑和 macOS 对 `~/Documents` 目录的权限提示有关。
